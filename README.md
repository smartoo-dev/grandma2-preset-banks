# PresetBanks для grandMA2

Плагин на Lua, который одним запуском заполняет пул пресетов набором цветов
или пул эффектов набором готовых эффектов — диммерных, позиционных, цветовых.

```
SetVar $PB "color 101 full"  ; Plugin "PresetBanks"    24 цвета   → Preset 4.101 … 4.124
SetVar $PB "dim 1 basic"     ; Plugin "PresetBanks"    5 эффектов → Effect 1.1 … 1.5
SetVar $PB "pos 10 basic 20" ; Plugin "PresetBanks"    4 эффекта, размах ±20°
SetVar $PB "colorfx 20 basic"; Plugin "PresetBanks"    4 цветовых эффекта
```

Смысловой аналог [одноимённого плагина для
grandMA3](https://github.com/smartoo-dev/grandma3-preset-banks) — но **не его
порт**. Почему так, разобрано в первом же разделе: попытка перенести решение
MA3 строку в строку дала бы неработающий код.

## Чем MA2 отличается от MA3

Различия не косметические: они меняют конструкцию, а не синтаксис.

| | grandMA3 | grandMA2 |
|---|---|---|
| универсальный прибор | есть (`Universal 1`) | **нет** |
| откуда берутся значения | с универсального прибора | **с текущей выборки** |
| эффекты | фейзеры внутри пресета | **отдельный пул** `Effect 1.x` |
| описание эффекта | шаги и слои шагов | линии: форма, low/high, phase, width, rate |
| «работает на всех» | `Store /Universal` | пресеты: `Store /u`; эффекты: режим **Template** |
| Lua API | `Cmd`, `MessageBox`, `GetPresetData` | `gma.cmd`, `gma.gui.*`, `gma.show.getobj` |
| диалог с полями | `MessageBox` с inputs и states | **нет** — только `msgbox`, `confirm`, `textinput` |
| передача аргумента | вторым параметром `Main` | **пользовательская переменная** |

Три следствия, которые видно в работе:

**Банк цветов требует выбранных приборов.** Универсального прибора в MA2 нет,
значения брать неоткуда — они задаются реальной выборке, а переносимость даёт
опция `/u` при сохранении. Плагин спрашивает подтверждение перед запуском:
проверить выборку из Lua нечем.

**Банки эффектов выборки не требуют.** Эффект собирается командами `Assign`
и к приборам не привязывается, поэтому остаётся **шаблоном** — в углу объекта
пула буква `T` (Template), «годен для всех приборов, у которых есть эти
атрибуты». Это и есть аналог универсального пресета MA3 для эффектов.

**Эффекты описываются иначе.** В MA3 эффект — это шаги со слоями. В MA2 —
линии с формой из пула Form, диапазоном low/high, фазой и шириной. Круг в MA2
делается не сдвигом фазы на 90°, а синусом по Pan и косинусом по Tilt: косинус
и есть этот сдвиг.

## Банки

| Банк | Куда пишет | Выборка | Число в аргументе | Умолч. номер | Элементов |
|---|---|---|---|---|---|
| `color` | `Preset 4.x` | **нужна** | — | 101 | 36 |
| `dim` | `Effect 1.x` | не нужна | скорость (1…3000, по умолч. 60) | 1 | 5 |
| `pos` | `Effect 1.x` | не нужна | размах ° (1…180, по умолч. 20) | 10 | 7 |
| `colorfx` | `Effect 1.x` | не нужна | скорость (1…3000, по умолч. 60) | 20 | 5 |

| Банк | Наборы |
|---|---|
| `color` | `basic` 12, `full` 24, `tint` 12 |
| `dim` | `basic` 5, `full` 5 — Sine, Pulse, Bump, Ramp, Strobe |
| `pos` | `basic` 4, `shapes` 3, `full` 7 — Circle, Pan/Tilt Sweep, Figure 8, Diagonal, Square, Nod |
| `colorfx` | `basic` 4, `full` 5 — Rainbow, Warm/Cold Drift, Red-Blue, Police |

Умолчания номеров разведены намеренно: банки эффектов делят один пул
`Effect 1.x`, и сходящиеся умолчания были бы ловушкой.

## Установка

**1.** Скопируйте `presetbanks.lua` в папку плагинов:

| Платформа | Путь |
|---|---|
| Windows / onPC | `C:\ProgramData\MA Lighting Technologies\grandma\gma2_V_<версия>\plugins\` |
| Консоль | тот же каталог `plugins` на внутреннем диске или USB |

Точное имя каталога зависит от версии ПО — оно содержит номер версии.

**2.** На консоли откройте пул Plugins, отредактируйте пустую ячейку и укажите
в ней имя файла `presetbanks.lua` и имя плагина `PresetBanks`.

**3.** Проверка:

```
SetVar $PB "list" ; Plugin "PresetBanks"
```

Откроется окно со списком банков.

> XML-обёртки для импорта в комплекте нет намеренно: схему файла плагина MA2
> я не проверял, а выдумывать её в файле, который пойдёт на консоль, — плохая
> идея. Присвоение `.lua` вручную работает и документировано.

## Запуск

Аргумент передаётся пользовательской переменной — обычный для MA2 способ:

```
SetVar $PB "<банк> <номер> [набор] [число] [префикс…]"
Plugin "PresetBanks"
```

| Команда | Что делает |
|---|---|
| `SetVar $PB "color 101 full"` | 24 цвета → `Preset 4.101` … `4.124` |
| `SetVar $PB "color 201 tint"` | 12 пастельных |
| `SetVar $PB "dim 1 basic"` | 5 диммерных эффектов → `Effect 1.1` … `1.5` |
| `SetVar $PB "pos 10 shapes 40"` | 3 фигуры, размах ±40° |
| `SetVar $PB "colorfx 20 full 90 Show"` | 5 цветовых, скорость 90, префикс имени `Show` |
| `SetVar $PB "dim"` | только банк — остальное из умолчаний |
| `SetVar $PB "list"` | банки и наборы |
| `SetVar $PB "help"` | синтаксис |

Переменная не задана — плагин спросит строку через `gma.textinput`.

**Правило разбора.** Первым идёт банк. Дальше нечисловые токены разбираются
**по типу**: совпал с ключом набора — набор, остальное — префикс имени; порядок
между ними любой.

⚠️ **Числа позиционны между собой:** первое — номер объекта, второе — параметр
банка. Два числа по виду не различить, поэтому «умного» разбора здесь нет: он
угадывал бы, а ошибка угадывания пишется в пул.

## Как это устроено

### Пресеты (банк `color`)

```
Clear
Attribute "ColorRGB1" At 100
Attribute "ColorRGB2" At 100
Attribute "ColorRGB3" At 100
Store Preset 4.101 /u /o /nc
Label Preset 4.101 "White"
```

| Что | Зачем |
|---|---|
| `Clear`, а не `ClearAll` | снимает значения, но сохраняет выборку — без неё писать нечего |
| `ColorRGB1..3` | имена цветовых атрибутов MA2; работают только у приборов с цветосмешением |
| `/u` | universal: пресет применим ко всем приборам, у которых есть эти атрибуты |
| `/o` | overwrite: содержимое номера заменяется целиком |
| `/nc` | noconfirm: иначе консоль ждёт подтверждения на каждом пресете |

### Эффекты (банки `dim`, `pos`, `colorfx`)

На примере `Pos Circle` при размахе 20:

```
Store Effect 1.10 /o /nc
Label Effect 1.10 "Pos Circle"
Store Effect 1.10.1 Thru 1.10.2 /o          ← создать две линии
Assign Attribute "Pan" Effect 1.10.1
Assign Effect 1.10.1 /mode="rel"
Assign Form 8 Effect 1.10.1                 ← 8 = Sin
Assign Effect 1.10.1 /rate=1
Assign Effect 1.10.1 /speed=60
Assign Effect 1.10.1 /phase=0
Assign Effect 1.10.1 /width=100
Assign Effect 1.10.1 /lowvalue=-20 /highvalue=20
Assign Attribute "Tilt" Effect 1.10.2
Assign Effect 1.10.2 /mode="rel"
Assign Form 9 Effect 1.10.2                 ← 9 = Cos, это и есть сдвиг на 90°
… те же параметры …
Assign Effect 1.10.2 /lowvalue=-20 /highvalue=20
```

Обращение к пулу эффектов всегда начинается с единицы — `Effect 1.10`, а не
`Effect 10`. MA Lighting заложили возможность нескольких пулов эффектов, но
так её и не использовали.

Ни одной команды, привязывающей эффект к приборам, здесь нет — поэтому он и
остаётся шаблоном.

## Откат и повторный запуск

**Идемпотентность.** Те же параметры → тот же результат: `/o` заменяет
содержимое номера. Прогонять дважды безопасно.

**Подтверждение перезаписи** — до первой команды записи, со списком занятых
номеров. Отключения нет.

**Откат:**

```
Delete Preset 4.101 Thru 4.124
Delete Effect 1.1 Thru 1.5
```

Точная команда печатается в командную строку и показывается в финальном окне
вместе с командой для повторения набора.

⚠️ Откат только для создания: прежнее содержимое перезаписанных номеров
`Store` уничтожает безвозвратно. Для первого прогона берите свободный диапазон.

## Номера форм — проверьте у себя

Эффекты ссылаются на формы из пула Form по номеру. В таблице `FORMS` в начале
файла:

```lua
local FORMS = { pwm = 4, sin = 8, cos = 9, circle = 19 }
```

⚠️ **Это не официальные значения.** Таблицы форм в документации MA нет; числа
взяты из рабочих макросов сообщества. Проверьте на своей консоли одним из двух
способов:

- откройте пул Form и прочитайте номера;
- выберите форму в редакторе эффектов и посмотрите обратную связь командной
  строки.

Номера другие — поправьте `FORMS`, остальной код от этого не зависит. Если
номер формы не тот, эффект создастся, но будет двигаться не так, как задумано:
отказа не будет, поэтому проверять надо глазами.

## Свой банк

Новый банк — запись в таблице `BANKS`, без строк движка.

```lua
{
  key = "beam", title = "Лучевые эффекты", kind = "effect",
  needsSelection = false,
  param = { name = "скорость", field = "speed", min = 1, max = 3000, default = 60 },
  defaultFirst = 30,
  defaultSet = "basic",
  sets = { { key = "basic", title = "Basic 1", members = { "Zoom Pulse" } } },
  items = {
    { name = "Zoom Pulse", note = "дыхание зума",
      lines = { line("Zoom", FORMS.sin, "abs", 20, 80) } },
  },
},
```

`line(атрибут, форма, режим, low, high, [фаза], [ширина])`. Режим `"abs"` —
абсолютные значения, `"rel"` — относительные, и тогда low/high умножаются на
размах из аргумента.

Банк с `kind = "preset"` описывает элементы полем `values` вместо `lines`;
готовый конструктор `colour(имя, r, g, b)` принимает RGB 0..255.

## Встроенные проверки

**Состав набора** — до первой команды: несуществующее имя в `members`
останавливает работу, ни один объект не пишется.

**Подтверждение выборки** для банков, которым она нужна. Проверить выборку из
Lua нечем, поэтому плагин спрашивает прямо, а не делает вид, что знает.

**Предупреждение банка** — показывается перед работой, а не прячется в
документации.

**Список занятых номеров** — до первой команды записи.

**Контрольный объект** — первый записанный читается обратно через
`gma.show.getobj.handle`. Нет объекта — остановка, остальные номера не
трогаются.

**`gma.gui.confirm` вызывается через `pcall`:** на версии 3.1.2.5 он подвешивал
консоль и требует 3.2 или новее. На старой версии получите отказ, а не зависшую
консоль.

Чего проверки **не** ловят: правильность номеров форм и то, окажется ли эффект
шаблоном. Первое даёт неверное движение без единой ошибки, второе смотрится по
букве в углу объекта пула.

## Разработка и тесты

```bash
lua5.4 test/stub-run.lua              # все 14 сценариев
lua5.4 test/stub-run.lua color        # пресеты + все команды первого элемента
lua5.4 test/stub-run.lua pos          # эффект целиком, обе линии
lua5.4 test/stub-run.lua swapped      # нечисловые токены в любом порядке
lua5.4 test/stub-run.lua numorder     # числа позиционны → отказ
lua5.4 test/stub-run.lua refuse       # отказ на подтверждении → ноль записей
lua5.4 test/stub-run.lua missing      # контрольный объект не создан → остановка
lua5.4 test/stub-run.lua novar        # переменная не задана → textinput
lua5.4 test/stub-run.lua busy         # диапазон занят
```

Заглушки подменяют всю таблицу `gma`: `cmd`, `echo`, `feedback`,
`gui.msgbox`, `gui.confirm`, `gui.progress.*`, `show.getobj.handle`,
`user.getvar`, `textinput`.

```bash
luac5.4 -p presetbanks.lua test/stub-run.lua
```

**Что заглушки не проверяют:** разбор команд консолью, движок эффектов, патч,
поведение `Store` и `Assign`, режим получившегося эффекта.

## Что не проверено

Код написан по документации MA Lighting, справочнику Lua API сообщества и
разборам на форуме MA; **на живой консоли не запускался.** Проверено: синтаксис
и 14 сценариев на заглушках.

Что посмотреть глазами при первом прогоне на onPC, в порядке важности:

1. **Номера форм** — см. отдельный раздел. Самая вероятная причина «эффект
   есть, но двигается не так».
2. **`/lowvalue` и `/highvalue` в режиме `abs`.** В разборе CLI сообщества эти
   параметры показаны на примере относительного режима; для абсолютного там
   предлагается путь через программер (`Store Effect 1.x /m`). Я использую их в
   обоих режимах. Не сработает в абсолютном — диммерный и цветовой банки
   придётся переводить на путь через программер, и тогда им понадобится
   выборка.
3. **Буква в углу объекта эффекта** — должна быть `T` (Template). Если `S`
   (Selective), эффект привязался к приборам и переносимым не будет.
4. **`Store Preset … /u`** на приборах разных типов: применяется ли пресет так,
   как ожидается.

Прогоняйте на копии шоу-файла, в свободном диапазоне, сначала маленьким
набором.
